# RHEL Enterprise Lab — Project Charter

## Purpose

Transform this repository from a collection of RHEL 10.2 guides into a professional, reproducible Enterprise Linux laboratory that serves four purposes:

1. Practical systems-administration training.
2. Controlled experimentation and incident-response practice.
3. Evidence-backed professional portfolio material.
4. A real infrastructure foundation for the wider Diego Alejandro Saenz Falcon technology ecosystem.

Every component must have an explicit operational reason, implementation method, verification method, evidence, and documentation.

## Scope

RHEL lifecycle management; identity and privilege; SELinux; firewalld; SSH; audit; systemd; journald; storage; LVM; networking; Git; Python; Podman; Bash/Python automation; monitoring; controlled failures; AI-assisted administration; documentation and evidence.

## Non-goals

- Running a large local LLM on the 8 GB laptop.
- Installing software without a documented operational purpose.
- Replacing Windows.
- Exposing unnecessary services.
- Storing credentials or personal secrets in Git.
- Claiming a control is implemented merely because it is documented.

## Definition of success

SPECIFIED → IMPLEMENTED → VERIFIED → EVIDENCED → DOCUMENTED

## Ecosystem role

- GitHub: durable source of truth.
- Directivas-de-Seguridad: central governance reference.
- AICCP: AI/agent orchestration.
- OpenCode: execution/development assistant, not authority.
- GitHub Pages: public professional presentation.
- Other repositories remain separate domains.

> Build the kind of RHEL environment that a systems engineer could explain, operate, troubleshoot, document and hand over inside a real company.
